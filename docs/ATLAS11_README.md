## 3. 매일 어떻게 돌아가나

1. `run_daily.mjs` 가 한국 시각·거래일(공식 휴장일 반영 달력)·정규장 마감(15:30)을 확인한다. 거래일이 아니거나 마감 전이면 채점만 하고 발행하지 않는다.
2. 수집기(`--collector 모듈`)가 있으면 종목별 확정 종가를 받는다. 관측값은 출처 URL(https·허용 호스트)·원문 해시·관측 시각·확정 근거가 있어야 하고, 16:00 전 관측은 제공자 확정 증거가 필수다. 이 환경에는 수집기를 연결하지 못했으므로 「시도 안 함 · 실패」로 기록되고 종료코드 2(부분)가 된다.
3. 어제까지 발행한 전망을 오늘 확정 종가로 채점한다(1·5·10·20거래일). 실현값 없는 목표일은 채점하지 않는다.
4. 52종목 전부 오늘 확정 종가가 확인될 때만 새 발행본을 만든다. 51개면 발행하지 않고 이전 발행본과 이유를 남긴다.
5. 같은 semantic 입력(가격·달력·뉴스 일정·정책·구현 해시)이면 기존 발행본을 재사용한다(새 파일 없음). 다르면 새 forecastId 로 불변 저장하고 latest 포인터를 원자적으로 바꾼다. 구현이 바뀌어도 새 버전이 되며 이전 버전은 남는다.
6. 화면 묶음을 다시 만들고 화면 간 일치를 검사한다.

## 4. 서버·예약·배포는 별도

- 이 저장소에 파일이 있다고 서버가 설치된 것이 아니다. Node 22 이상 작업 서버에서 장 마감 뒤(권장 15:40~16:00, 확정 종가 확인 우선) `npm run atlas11:daily` 를 예약하고, 끝나면 `dist/` 를 Netlify 에 올린다(`npm run atlas11:package` 후 Drop ZIP 또는 Netlify CLI).

### 9.2 연쇄 지도 — 이 종목이 흔들리면 (`lib/atlas11/network.mjs`, `site/app/view-network.js`)
- 식: 최근 2년(504거래일) 일별 로그수익률을 `r_j = β_j·m + ε_j` 로 나눈다(m = 52종목 등가중 평균 = 「시장 통로」, ε = 시장을 뺀 나머지 = 「직접 통로」).
- 종목 i 가 Δ 만큼 움직이면 → 시장 통로 `Δ_m = cov(m, r_i)/var(r_i)·Δ`, 종목 j 는 `β_j·Δ_m`; 직접 통로 `b^ε_ji·(Δ − β_i·Δ_m)` (잔차 이웃 상위 5, |ρ|≥0.15). 두 통로의 합은 `cov(r_j,r_i)/var(r_i)·Δ` 와 같다(항등식 · 단위 검사).
- 3차~5차: 직접 통로의 효과가 잔차 이웃 관계망(217개 간선)을 따라 감쇠 0.5 로 번지는 양(Katz 방식). 「친구의 친구」 노출을 보는 탐색값.
- 화면: 원형 지도(52점 · 9묶음 호 · 차수별 연결선 · 파급 크기 = 점 크기, 부호 = 색) · 충격 단추(−10/−5/+5/+10%) · 「누적으로 보기」 · 「▶ 파급 재생」(1차→5차 차례로 켜짐, 줄임 모션이면 즉시) · 1~5차 다섯 칸 표(각 칸 상위 5, 누르면 그 종목 상세로) · 「시장 통로와 직접 통로」 한 문장 · 읽어주기 문장.
