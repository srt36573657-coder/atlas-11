## 왜 v2 인가
- v1 의 결론 숫자(고를 때 안 본 기록 A = 33.25%)는 **달마다 다시 고르는 법**의 기록이다. 그런데 사이트는 11월 2일부터 하나로 굳힌 조건(big2&ix4)으로 골랐다 — 광고한 기록과 실제로 도는 법이 조금 다르다.
- v2 는 사이트가 **그 법 그대로** 달마다 스스로 다시 고르게 한다 → 결론 숫자와 실제로 도는 법이 같아진다.

## 1. 결정(달 M)
- s = 자료에 있는 M 의 첫 거래일. 배우는 날 = T0 ≤ t ≤ s − 20(날 차례로 셈 · 결과가 s 까지 난 날).
- 들 수 있음 · 점수 LB · 고르기 = v1 그대로(n ≥ 300 · 고른 날 ≥ 배우는 날의 40% · 고른 날 하루 평균 ≤ 20 · 크게 떨어짐 ≤ 같은 날 아무 회사 + 2 · LB = d − 1.645 × se(20날 덩어리) · 가장 큰 LB · 같으면 n 큰 것 · 그다음 이름 차례).
- 들 수 있는 것이 없으면 그 달은 고르지 않음(0곳 · 결정 id 없음).
- 결정하는 달 = 배우는 날이 250 이상인 첫 달부터 **s 가 자료에 있는 마지막 달까지**(v1 은 TL 이 든 달까지였음 — v2 는 결과가 아직 없는 달도 결정한다).

## 2. 봉인
- **2026-11 부터의 결정은 처음 낸 대로 둔다**(`site/next/data/bloom-months.json` 에 적힌 것). 뒤에 자료가 바뀌어 다시 세면 다른 것이 나와도 바꾸지 않고 「다시 세면 다름」만 적는다.
- 2026-10 까지는 「지난 기록으로 돌려 본 달」 — 돌릴 때마다 그때 자료로 다시 센다(봉인 아님).

## 3. 달 기록(점수 바탕)
- 달 M 의 결정 r 로, t ∈ M 이고 T0 ≤ t ≤ TL(= N − 21 · 결과가 난 마지막 날)인 날마다: 고른 회사 = SPROUT & BASEM & r(v1 셈 그대로).
- n(고른 수) · h(그중 꽃) · nb(같은 날 아무 회사 = BASEM) · hb(그중 꽃) · days(그 날 수) · pickDays(고른 회사가 있는 날 수).
- 그 달 날이 모두 t ≤ TL 이고 다음 달 s 가 자료에 있으면 「다 셈」, 아니면 「세는 중」.

## 4. 점수
- 달 점수 = 100 × (h / n − hb / nb) — 「100번에 몇 번 더(덜)」. n = 0 이면 점수 없음(그 달은 고른 회사가 결과 난 날에 없었음).
- 모은 점수 = 2025-01 부터 결과가 난 모든 달을 합친 h · n 과 hb · nb 로 같은 셈(이것이 쪽 · 첫 화면의 결론 숫자 — v1 의 wf.A + test 를 갈음).

## 5. 교차 검증(셈 셋)
- ① 연구 셈 `scripts/atlas11/research/bloom_evolve.py` ② 따로 센 일꾼 `docs/design/bloom-evolve-2026-11-02/recount-independent.py`(이 약속과 자료만 보고 짠 것 · 연구 셈 코드를 보지 않음) ③ 사이트 엔진 `site/next/theme-engine.js` + `site/next/bloom-atoms.js`.
- 같은 자료로: 달마다 결정 id(① = ②) · 달 기록 n · h · nb · hb(① = ② = ③ · 엔진은 결정을 받아 기록만 셈).
- **셋이 모두 같을 때만** `bloom-months.json` 을 새로 적는다. 하나라도 다르면 새 결정을 넣지 않고(가장 최근 결정을 이어 씀) 「셈 셋이 달라 바꾸지 않음」과 다른 숫자를 적는다.

## 6. 사이트
- 날 t 의 조건 = t 가 든 달의 결정. 그 달 결정이 아직 없으면 가장 최근 결정을 이어 쓰고 「이번 달은 아직 고르기 전」이라고 보인다.
- 회사마다 까닭 = 그날 그 달 조건의 두 낱 조건 이름 · 지난 기록 = 이 회사가 2025-01 부터 달마다 조건에 든 날 · 그중 꽃.

## 7. 언제 도나
- 깃허브 일(`.github/workflows/atlas11-bloom-month.yml`) — 지금 사이트 자료를 받아(큰 검사와 같은 sha256 받기) ① ② ③ 을 돌리고, 셋이 같을 때만 main 에 `bloom-months.json` · 그날 연구 결과를 적는다.
- 평일 저녁(서울 17시 대 · 그날 자료가 올라온 뒤) 예약 작업이 깃허브 일을 부르고, 결과를 카톡으로 알린다. 새 달 첫 거래일 자료가 오면 그 달 결정을 낸다. 같은 달 두 번째부터는 기록 · 점수만 새로 셈.
