## 0. 한 줄로

n = 사이트 자료의 마지막 날에서 250거래일 앞 날(「그날」)까지 5거래일 동안 가장 많이 오른 36곳 가운데, 그 뒤 250거래일 안에 종가가 그날 종가의 절반보다 작았던 날이 하루라도 있는 곳의 수.

## 1. 읽는 파일(읽기만 · 고치지 않음)

`<site>` = 명령의 `--site` 값(없으면 `site`).

| 파일 | 쓰는 칸 |
|---|---|
| `<site>/atlas/data/days.json` | `dates` — 거래일 글 배열 `'YYYY-MM-DD'` |
| `<site>/atlas/data/mkt.json` | `asOf` · `companies`(열쇠 = 종목 번호 글 · 값의 `n` = 이름) |
| `<site>/atlas/data/co/<번호>.json` | `k0`(정수) · `close`(배열) |
| `<site>/atlas/data/surge.json` | alt(§9) 에만: `members`(배열 · 칸 `c` = 번호) · `asOf` · `kst` |

다른 칸(co 의 `c` · `jumps` · `c.mdd1y` · `c.name`, surge 의 `half` · `facts` 등)은 셈에 쓰지 않는다. 이름도 mkt.json 에서만 읽는다(co 파일 가운데 `c` 칸이 없는 것이 있음).

## 2. 이름과 기호

- N = `dates` 길이. 날 번호 t = 0 … N−1. L = dates[N−1](마지막 날).
- v(c, t) = 회사 c 의 날 t 종가: t < k0 이면 「빈 값」, 아니면 close[t − k0].
- 「쓸 수 있는 값」 = JSON 수(참 · 거짓 아님) · 유한 · 0 보다 큼. 그 밖(null · 0 · 음수 · 글 · 배열 밖)은 「빈 값」. 값은 반올림 · 고침 없이 그대로 쓴다.
- jump(p, x) — 「하루에 크게 바뀜」: 앞의 쓸 수 있는 값 p 와 그다음 쓸 수 있는 값 x 에서 |x − p| × 100 > p × 35 이면 참. 나눗셈이 아니라 이 곱셈 꼴로 견준다. 까닭: 한국 하루 값 제한이 ±30% 라 35% 넘게 바뀐 날은 주식 수 바뀜 · 다시 매김 · 자료 틀림일 수 있다(사이트 급등 칸 sv-v1 의 「하루 35% 넘게 바뀐 날」과 같은 잣대).
- below(x, b) — 「반값 아래」: 2 × x < b. 종가 x 가 기준 b 의 절반보다 작을 때만 참이다. 꼭 절반(2 × x = b)은 아래가 아니다. 장 중 가장 낮은 값은 보지 않는다(종가만).

## 3. 멈춤(아무 파일도 쓰지 않고 끝 코드 1 · 까닭을 찍음)

- days.json 을 못 읽음 · `dates` 가 글 배열이 아님 · 날이 엄격한 오름차순이 아님(같은 날이 둘이어도 멈춤) · N < 256(그날의 5일 창이 자료 밖).
- mkt.json 을 못 읽음 · `companies` 가 비었음 · `mkt.asOf` ≠ L.
- `companies` 의 어느 번호든: co 파일이 없음 · 못 읽음 · `k0` 가 0 이상 정수가 아님 · `close` 가 배열이 아님 · k0 + close 길이 ≠ N.
- 그날(§4)에 들 수 있는 곳이 36곳보다 적음.
- surge.json 문제로는 멈추지 않는다 — alt = null(§9).

## 4. 그날

- i0 = N − 1 − 250. 그날 `day` = dates[i0]. 5일 창 = 날 i0−5 … i0(값 여섯 개). `from` = dates[i0 − 5].
- 「1년」 = 250거래일. 거래일은 days.json 의 날로만 센다(회사마다 값이 있는 날로 세지 않는다).

## 5. 모집단과 고르기(날 i 에서 — 그날은 i = i0, spread 는 §8)

- 모집단 = mkt.json `companies` 의 열쇠 모두(사이트의 코스피 · 코스닥 보통주 그대로). `universe` = 그 수.
- 「들 수 있음」: v(c, i−5) … v(c, i) 여섯이 모두 쓸 수 있는 값이고, 붙은 짝 다섯(i−5→i−4, i−4→i−3, …, i−1→i) 어디에도 jump 가 없음. `eligible` = 그날 들 수 있는 곳 수.
- 5일 오름 비 q = v(c, i) ÷ v(c, i−5) — IEEE 754 배정밀도 나눗셈 한 번(뺄셈 · 곱셈을 먼저 하지 않음).
- 차례: q 가 큰 것 먼저. q 가 똑같으면 번호 글의 글자 차례(작은 것 먼저 · 글자 코드 차례 — 번호는 숫자와 영어 대문자뿐).
- 고른 곳 = 차례 앞 36곳. 들 수 있는 곳이 36보다 적으면: 그날이면 멈춤(§3), spread 의 날이면 그 날을 건너뜀.
- 하지 않는 것: 거래량 · 거래대금 · 새 상장 · 거래정지 표시 · 그날 사이트 급등 칸에 들었는지를 보지 않는다(사이트 자료에 거래량이 없다). 그래서 이것은 「그날의 급등 칸 36곳」이 아니라 「그날까지 5일 오름 상위 36곳」이다.

## 6. 그 뒤 1년(고른 곳 c 하나 · 날 i)

- 기준 b = v(c, i). 끝 E = min(i + 250, N − 1). 보는 날 t = i+1 … E. 그날(i0)이면 E = N−1 = L 이고 꼭 250날이다.
- prev = b, gap = 거짓으로 시작해 t 를 차례대로 하나씩:
  1. v(c, t) 가 빈 값이면 gap = 참 · 다음 날로.
  2. x = v(c, t). jump(prev, x) 이면 → 「모름」(why = `'jump'`, jumpDay = dates[t]) · 그만 봄.
  3. below(x, b) 이면 → 「예」(halfDay = dates[t]) · 그만 봄.
  4. prev = x.
- 끝까지 봤으면: gap 이 참이면 「모름」(why = `'gap'`), 아니면 「아니오」.
- 한 날이 jump 이면서 반값 아래면 「모름」이다(2 가 3 보다 먼저). 반값 아래가 jump 보다 먼저 나왔으면 이미 「예」라 뒤의 jump 는 상관없다.
- 표시용(판단에 안 씀): `min` = t = i+1 … E 의 쓸 수 있는 값 가운데 가장 작은 값(그만 본 뒤의 날도 모두 넣음) · `minDay` = 그 값이 처음 나온 날. 쓸 수 있는 값이 하나도 없으면 둘 다 null.

## 7. 그날의 숫자

- `n` = 고른 곳 가운데 「예」의 수. `unknown` = 「모름」의 수. `of` = 고른 곳 수(36).
- n 은 「적어도 n곳」이다. 모름 · 사라진 회사 · 종가만 보기는 적게 셀 수는 있어도 많이 세지는 않는다(§12).

## 8. spread — 그날이 흔한 날인지(리드 2026-10-18)

- 날 i = 5 … N − 251 모두, 작은 차례로(5일 창이 자료 안에 있고 그 뒤 250날이 모두 자료 안에 있는 날 · 마지막 i = N − 251 = i0 그날 포함).
- 날마다 §5 로 36곳(모자라면 그 날 건너뜀) → 곳마다 §6(E = i + 250) → n_i(「예」 수) · unknown_i(「모름」 수).
- `spread` = {`days`: 쓴 날 수, `from`: 쓴 첫 날 dates[i], `to`: 쓴 마지막 날, `min`, `median`, `max`, `mean`, `lower`: n_i < n 인 날 수, `higher`: n_i > n 인 날 수, `unknownDays`: unknown_i > 0 인 날 수} — 여기 n 은 §7 그날의 n.
- median: n_i 를 작은 차례로 늘어놓고, 날 수가 홀수면 가운데 값 · 짝수면 가운데 둘의 평균(소수 .5 일 수 있음).
- mean: n_i 합 ÷ days 를 소수 첫째 자리로 반올림(JS `Math.round(x * 10) / 10`). 맞대기는 ±0.05.
- 쓴 날이 하나도 없으면 spread = null(그날이 있으면 생기지 않음).

## 9. alt (나) — 지금 급등 칸 곳들(화면에 안 씀 · 참고)

- 고른 곳 = surge.json `members` 의 `c`(파일 차례 그대로 · 글이 아닌 것은 뺌). `of` = 그 수.
- 곳마다 창 = 날 max(0, N − 250) … N − 1. peak = 없음, prev = 없음, cnt = 0, gap = 거짓, cut = 거짓으로 시작해 t 를 차례대로:
  1. t < k0 이면 넘어감(상장 전 — 빈 칸으로 치지 않음).
  2. v(c, t) 가 빈 값이면 gap = 참 · 다음 날로.
  3. x = v(c, t). prev 가 있고 jump(prev, x) 이면 cut = 참 · peak = 없음(크게 바뀐 날 앞뒤를 서로 견주지 않음).
  4. peak 가 있고 below(x, peak) 이면 → 「예」 · 그만 봄.
  5. peak = (peak 없음이면 x, 아니면 max(peak, x)) · prev = x · cnt = cnt + 1.
- 끝까지 봤으면: cut 이 참이거나 gap 이 참이거나 cnt < 60 이면 「모름」, 아니면 「아니오」.
- 그 번호의 co 파일이 없음 · 못 읽음 · k0 가 0 이상 정수가 아님 · close 가 배열이 아님 · k0 + close 길이 ≠ N 이면 「모름」.
- `alt` = {`rule`: `'h36-b'`, `n`: 「예」 수, `of`, `unknown`: 「모름」 수, `asOf`: surge.json `asOf`(없으면 null), `kst`: surge.json `kst`(없으면 null)}. surge.json 을 못 읽거나 `members` 가 배열이 아니면 `alt` = null.
- 참고(셈에 안 씀): 사이트 co 파일의 `c.mdd1y` = 그 회사 제 값 마지막 252개에서 앞 꼭대기 대비 가장 깊이 빠진 % (값 60개 밑이면 null · 소수 둘째 자리). `c.mdd1y ≤ −50` 은 이 alt 와 거의 같은 뜻이다(다른 점: 제 값 252개 · 「반 이하」 · 반올림 · jump 를 안 봄).

## 10. 쓰는 꼴 — `site/next/data/half36.json`(한 줄 JSON + 줄바꿈)

{`schema`: `'kkolttori-half36-1'`, `rule`: `'h36-a'`, `n`, `of`, `unknown`, `day`, `from`, `until`, `asOf`, `window`: 250, `eligible`, `universe`, `made`, `list`, `alt`, `spread`, `note`, `check`}

- `until` = dates[E](그날은 L) · `asOf` = L · `made` = 만든 때 UTC `'YYYY-MM-DDTHH:MM:SSZ'`(밀리초 없음).
- `list` = 고른 곳을 §5 차례대로, 곳마다 {`code`, `name`, `rise5`, `close`, `min`, `minDay`, `half`, `halfDay`, `why`, `jumpDay`}

  - `half` = true(예) · false(아니오) · null(모름) · `halfDay` = 「예」면 그 날, 아니면 null · `why` = 「모름」이면 `'jump'` 또는 `'gap'`, 아니면 null · `jumpDay` = why 가 `'jump'` 면 그 날, 아니면 null.
- `note` = 쉬운 말 한국어(어떻게 셌나 · 적게 셌을 수 있음) — 맞대지 않음.
- `check` = 따로 세기를 지난 뒤 {`by`: `'half36_verify.py'`, `ok`: true, `at`: 때 UTC} · `--no-verify` 로 쓴 판은 null(따로 세기 전 — 올리는 판은 null 이면 안 됨).

## 11. 따로 세기 약속(KG2)

- 부르는 법: `python3 scripts/atlas11/next/verify/half36_verify.py --site <site> --json <후보 파일>` — 이 표만 보고 처음부터 셈해 후보 파일과 맞댄다.
- 맞대는 칸: `schema` · `rule` · `n` · `of` · `unknown` · `day` · `from` · `until` · `asOf` · `window` · `eligible` · `universe` 는 그대로 · `list` 는 길이와 차례 · 곳마다 `code` · `name` · `close` · `min` · `minDay` · `half` · `halfDay` · `why` · `jumpDay` 는 그대로, `rise5` 는 ±0.01 · `alt` 는 null 인지 · `rule` · `n` · `of` · `unknown` · `asOf` · `kst` 그대로 · `spread` 는 null 인지 · `mean` ±0.05 · 나머지 칸 그대로. `made` · `note` · `check` 는 맞대지 않는다.
- 끝 코드: 0 = 틀림 0 · 1 = 틀림 있음(틀린 칸과 두 값을 찍음) · 2 = 셈을 못 함(파일을 못 읽음 등).
- half36.mjs 는 후보를 임시 파일에 쓰고 따로 세기를 부른다 → 끝 코드 0 일 때만 `half36.json` 을 바꾼다(그때 `check` 를 채움). 따로 세기 파일이 없으면 쓰지 않고 끝 코드 2. `--no-verify` 를 주면 따로 세기 없이 쓰고 `check` = null.

## 12. 적게(또는 다르게) 셀 수 있는 까닭 — 숨기지 않는다

1. 사라진 회사: 사이트 자료에는 지금 상장된 회사만 있다. 그사이 상장이 폐지된 회사(크게 떨어져 사라졌을 수 있다)는 고르기에도 세기에도 없다. 그래서 n 은 실제보다 작을 수 있다. 고른 36곳도 「지금까지 살아남은 회사 가운데」 상위다.
2. 종가만: 장 중에 반 아래로 내려갔다가 그 위에서 끝난 날은 「예」가 아니다.
3. 모름: 하루에 35% 넘게 바뀐 날이나 빈 값 때문에 「모름」이 된 곳은 n 에 넣지 않는다. 35% 안쪽의 주식 수 바뀜(예: 3주를 2주로)은 걸러지지 않는다.
4. 거래정지: 멈춘 동안 같은 값이 이어지면 떨어짐이 안 보인다. 아직 멈춘 채인 회사는 「아니오」로 셀 수 있다.
5. 한 날: n 은 그날 하나에 기댄다. 며칠만 옮겨도 n 이 크게 바뀐다 — 그래서 `spread` 를 함께 둔다.
6. 저녁 장: 네이버 종가는 넥스트레이드 저녁 장까지 든 값일 수 있어 하루 30% 를 조금 넘게 바뀐 날이 있다. 35% 잣대라 이런 날은 그대로 센다.
7. 급등 칸과 다름: 사이트 급등 칸의 고르기(거래대금 1억 원 · 새 상장 · 멈춤 빼기 · 들고 남는 규칙)를 따르지 않는다.
