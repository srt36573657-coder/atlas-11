할 일
1. 이미 도는 작업이 있는지 본다 — atlas11-site.yml · atlas11-daily.yml · atlas11-evening.yml · atlas11-us.yml 각각:
   gh run list -R srt36573657-coder/atlas-11 --workflow <작업 파일> --limit 3 --json databaseId,status,conclusion,createdAt
   status 가 queued 또는 in_progress 인 실행이 있으면 새로 누르지 말고 그 실행이 끝날 때까지 기다린다(gh run watch <databaseId> -R srt36573657-coder/atlas-11 --interval 60 · 최대 45분). 그 실행이 atlas11-site.yml 이고 시작한 지 10분 안이면 이번 회차의 올리기로 치고 3 으로 간다. 45분을 넘기면 「앞 업데이트가 아직 돌아 이번은 건너뜀」으로 끝낸다.
2. 올리기를 누른다:

   <회차> 는 지금 한국 시각에 가장 가까운 정각이다(예: 21:00).

지킬 것
- 저장소의 어떤 파일도 고치거나 커밋하지 않는다. 예약 작업 파일(atlas11-daily.yml · atlas11-evening.yml)은 고치지 않는다. atlas11-site.yml 말고 다른 깃허브 일을 누르지 않는다. 다른 예약 작업을 고치거나 끄지 않는다.
- NETLIFY_AUTH_TOKEN · NETLIFY_SITE_ID 같은 비밀 값을 찾거나 적지 않는다. siteId · deployUrl · deployId 를 적지 않는다.
- 주가를 맞히는 말, 사고팔기를 권하는 말, 수익률을 쓰지 않는다. 시장 판독은 기록에 적힌 지난 사실만 옮긴다.
- 점검 실패 · 자료 부족을 통과로 적지 않는다. 장이 없는 때(밤 · 주말 · 휴장)는 결과가 「그대로」인 것이 맞다. 없으면 없다고 적는다.
