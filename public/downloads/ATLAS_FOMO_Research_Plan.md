# ATLAS 52종목 FOMO 연구·도입 기획서

문서 상태: 연구 설계 / 운영 예측 반영 전. 검토 대상: ATLAS 9.0.0, 기존 atlas-fomo-1.0.0. 보관 종가 기준: 2026-09-23. 목표 기간: 2026-09-17~10-30 유지.

## 1. 결정할 방향

종목마다 ‘놓칠까 봐 뒤늦게 사려는 압력’을 관측자료로 추정한다. 검색이 늘었다는 사실만으로 매수 심리를 확정하지 않는다. 관심 증가, 거래 참여, 상승 추격이 함께 나타나는지 측정하고, 이미 가격이 많이 올라 되돌림에 취약한지도 따로 계산한다.

화면에는 이해하기 쉬운 FOMO 지수 하나를 표시한다. 예측 엔진에는 그 숫자 하나만 넣지 않고 관심·추격·과열 구성값을 넣는다. 같은 FOMO 80점이어도 삼성전자와 올릭스의 예상 반응, 상승 지속 기간, 하락 위험은 달라질 수 있다. 80점은 상승 확률 80%가 아니다.

선택한 방식은 ‘관측 지수 + 기존 예측의 오차를 설명하는 작은 조건부 모형’이다. 처음부터 복잡한 AI로 52개 별도 모형을 만들기보다 설명 가능하고 검증 가능한 후보부터 시작한다. 아래 방정식은 ATLAS용 제안이며 이미 학계에서 검증된 완성 공식이라는 뜻이 아니다.

## 2. 현재 실제로 있는 것과 없는 것

기존 lib/fomo.mjs에는 18개 특징, 최근 10거래일 창, 최대 252개 과거 비교 창, 최소 60개 비교값 조건이 있다. 그룹 안의 상관관계를 이용해 중복 가중치를 줄인다. 현재 보관된 52종목 보고서는 모두 6/18항목이며 종합 점수는 자료 부족이다. 확보된 6항목은 종가 기반 가격 열기다. priceWeight=0, forecastIntegration.enabled=false다.

lib/fomo-validation.mjs는 종목별 완전한 18항목, 당시 원본·조정 확인, 비중복 10거래일 목표 자료를 골라 최소 학습 30개·시험 10개를 요구한다. 점수를 중심화해 기존 예측의 로그수익률 오차에 선형 계수 하나를 맞춘다. 실제 운영 반영은 꺼져 있다.

이 출발점은 원본 보호에 유용하지만, 18개가 모두 있어야 한다는 조건은 합법적 수집이 어려운 게시자 자료 하나 때문에 전체 연구를 막을 수 있다. 선형 계수 하나는 상승 지속과 과열 반전을 구분하기 어렵고, 마지막 10개 시험만으로 안정성을 증명하기도 부족하다. 최소 표본 숫자 자체는 정확도 인증이 아니다.

이번 작업은 기존 코드·상태와 1차 연구 및 공식 문서를 대조해 기획서를 작성한 것이다. 새 52종목 원자료 수집, 계수 학습, 운영 반영, 실전 성능 검증을 완료한 작업은 아니다.

## 3. 학습한 근거와 적용 한계

1. Da·Engelberg·Gao의 2011년 논문은 미국 종목의 검색 관심 증가와 단기 가격 상승 및 이후 반전의 관계를 보고한다. 관심은 가격·거래량 대용 지표와 완전히 같지 않았다. 따라서 검색을 추가할 연구 근거는 있지만 그 계수와 기간을 한국 52종목에 그대로 복사할 수 없다. 검색 관심은 감정이나 매수 의도의 직접 측정도 아니다. [S1]
2. KRX 데이터 메뉴에는 개별종목 시세와 투자자별 거래 자료가 있다. 이는 데이터 확보 경로이며 52종목 자료를 이미 내려받았다는 증거가 아니다. 접근권한, 제공 범위, 공개 지연, 이용 조건부터 확인한다. [S2]
3. NAVER 데이터랩은 검색어 묶음과 일별 조회를 지원한다. 결과는 최대치를 100으로 둔 상대값이고 인증 정보가 필요하다. 2016년부터 조회 가능하다고 안내하지만 당시 저장 원본을 지금 복구해 준다는 뜻은 아니다. [S3]
4. Google도 검색 지수를 정규화한 상대값으로 설명한다. 서로 다른 요청의 숫자를 원시 검색 건수처럼 비교하지 않는다. 본문 재접속 실패는 검색 결과 확인과 구분해 남긴다. [S4]

실무적 결론: ‘가격이 올라서 FOMO가 높고, FOMO가 높아서 가격이 오른다’는 순환 설명을 피하려면 가격만으로 만든 모형과 검색·수급을 추가한 모형을 분리해 비교해야 한다.

검색 조회는 기본 최대 5묶음씩 52종목을 11묶음으로 나누되 실제 요청·기간 제한을 따른다. 동일 요청 안의 최근·과거 비율을 사용하고 queryId, 기간, 필터, 응답 원문 해시를 저장한다. 배치 간 절대 검색량 비교는 하지 않는다. 동시성은 제공자별 제한에 맞춰 제한하고, 실패 종목은 나머지 종목을 막지 않는다.

각 값은 code, sessionDate, publishedAt, observedAt, sourceUrl, snapshotHash, unit, adjustmentVersion, queryVersion, quality를 갖는다. 16시 실행은 시작 시각이며 모든 항목이 16시에 확정 공개된다는 보장이 아니다. 늦게 들어온 자료는 새 버전에서 사용하고 과거 발행본에 몰래 채워 넣지 않는다. 휴장일에는 직전 거래일의 관측값임을 표시한다.

## 6. 수학 설계 A — 종목별 FOMO 관측 지수

i는 종목, t는 기준 거래일, j는 특징이다. 현재 관측 창 W는 t−9부터 t까지 10거래일이다. 기준 창 B는 그보다 앞선 60거래일을 우선 사용한다. 가격 위치 등 각 특징의 별도 필요 기간은 위 정의를 따른다.

```text
증가 특징 x(i,t,j) = mean_W(raw_j) / mean_B(raw_j) − 1
조건: 같은 정의·단위·검색 요청 척도, 유효 분모 > 0

q(i,t,j) = [Σ(s∈R) {1[x(i,s,j)<x(i,t,j)]
                      + 0.5×1[x(i,s,j)=x(i,t,j)]}] / |R|
```

R은 현재 10일 창이 시작하기 전에 끝난 같은 종목의 과거 특징 창이다. 기본 최대 252개 비교 창으로 시작한다. 60개 미만이면 표시를 유보한다. 비교 창들이 겹치므로 252개의 독립 시험이라는 뜻이 아니다. q는 0~1의 자기 과거 대비 위치다.

핵심 지수는 검색 관심 A, 거래 참여 V, 추격 C의 세 축으로 시작한다. 첫 후보의 A는 17번, V는 7·14번, C는 9·12·13번의 q 평균이다. 그룹별 구성은 버전에 고정하며 하나라도 빠지면 다른 특징의 가중치를 몰래 늘리지 않는다.

```text
A = q17
V = mean(q7, q14)
C = mean(q9, q12, q13)
FOMO_proxy = 100 × (A × V × C)^(1/3)
```

기하평균은 세 축이 함께 높을 때 높은 점수를 주려는 설계 선택이다. 이미 검증된 경제 법칙은 아니다. 0~100점이며 자기 과거 대비 관심·참여·추격 결합의 강도다. 단일 점수가 80이라고 정확히 역사적 상위 20%라는 뜻도 아니다. 그 표현이 필요하면 결합값 자체를 다시 과거 분포에 순위화한다.

기사·작성자 확장과 상관 중복 보정은 별도 사전 등록 후보로 비교한다. 핵심 6개 입력 확보형과 확장형의 이름·버전을 다르게 둔다. 가격만 있을 때는 지금처럼 ‘가격 열기’만 표시한다. 자료 확보율은 따로 표시하고 FOMO 점수에 곱하지 않는다. 자료가 부족하다고 시장의 열기가 낮아지는 것은 아니기 때문이다.

과열 O는 4번 이격과 15번 신용, 상승 둔화 등을 별도 특징으로 둔다. 신용 미확보 시 신용 없는 모형을 별도로 검증한다. 핵심 점수에 신용을 무조건 가산하지 않는다.

## 7. 수학 설계 B — 예측 가격에 반영

화면 점수만으로 ‘80점이면 +5%’ 같은 규칙을 만들지 않는다. 관심과 추격이 예측 오차를 실제로 줄이는지를 학습한다.

```text
실제 목표 y(i,t,h) = log(P(i,t+h) / P(i,t))
기존 예측 b(i,t,h) = 기준시각에 고정된 기존 모형의 기대 로그수익률
남은 오차 e(i,t,h) = y(i,t,h) − b(i,t,h)

φ(i,t) = [A, V, C, O, A×C, C×O, ΔA, ΔC]
δ(i,t,h) = a(i,h) + θ(h)'φ(i,t)
새 기대 로그수익률 = b(i,t,h) + δ(i,t,h)
```

a는 종목 차이, θ는 조건별 효과다. 계수의 부호를 미리 모두 양수로 강제하지 않는다. 관심·추격이 함께 높을 때의 지속 효과와 과열 때의 반전 효과는 데이터가 결정한다. Δ는 최근 구간과 직전 구간의 변화이며 정의를 모델 카드에 고정한다. 기사 내용·시장·업종·기존 가격 특징은 비교 양쪽에 같은 통제로 포함한다.

처음에는 작은 정규화 회귀로 시작한다. 학습 목적함수는 날짜별 평균 제곱 오차 + 계수 축소 항이다. 종목별 절편은 표본이 적을수록 공통값 쪽으로 축소하는 계층 모형 후보와 독립 종목 모형을 비교한다. 공동 계수 학습은 공통 정의의 특징에 한정하며 A기업 뉴스 반응을 B기업의 사건 표본으로 복사하지 않는다. 52종목 중 어떤 종목이 개선되지 않는지도 공개한다.

```text
min Σ(t∈학습일) mean_i[(e(i,t,h)−a(i,h)−θ(h)'φ(i,t))²]
    + λ ||θ(h)||² + κ Σ_i a(i,h)²
```

λ·κ, 변수 선택, 상호작용 유무는 학습 내부의 시간순 검증으로 선택한다. 외부 시험 결과를 보고 다시 유리한 값을 고르지 않는다. 기존 예측 b가 없다면 당시 정보만으로 재계산한 연구용 기준을 명확히 표시한다.

h별 목표는 우선 1·5·10거래일을 비교한다. 최종 운영 그래프에는 검증된 일별 경로 모형 하나를 사용한다. 서로 따로 학습한 1·5·10일 값을 임의 곡선으로 이어 붙여 10월 30일 경로라고 하지 않는다. 장기 경로는 상태의 전이·소멸 속도까지 학습한 일별 모형에서 누적한다. 미래 검색량·수급을 관측 사실처럼 채우지 않는다.

```text
일별 경로 log P(t+h) = log P(t) + Σ(k=1..h) [b_increment(k)+δ_increment(k)+ε(k)]
```

상태 전이와 잔차는 학습 기간에서 추정하고 공통 시장 충격·시간 의존성을 보존한다. 경로의 중앙값을 그래프 중심으로, 분위수를 범위로 계산한다. exp(기대 로그가격)을 산술 평균가격이라고 부르지 않는다. 기존 변동성과 FOMO 잔차 변동성을 독립이라고 가정해 단순 합산하지 않고 결합 모형의 잔차로 재추정한다.

최초 9/17 전망은 보존한다. 이후 알게 된 FOMO는 이후 발행하는 진화 전망에만 반영한다. 현재 52종목에는 검증된 δ가 없으므로 운영 계수는 0 유지가 현재 상태이며, 개발 중인 후보는 별도 연구 기록에 남긴다.

## 8. 검증 설계 — 실제로 추가 가치가 있는가

동일 날짜·동일 자료 조건에서 네 후보를 비교한다: 기존 모형, 가격 열기만 추가, 검색·참여 핵심 추가, 과열 상호작용 추가. 가격 열기만으로 설명되는 효과를 새로운 FOMO 효과라고 부르지 않는다.

시간순 바깥 시험과 그 안의 학습·계수 선택을 분리한다. 10일 목표가 겹치는 학습 표본은 시험 경계에서 제거한다. 추가 간격은 피처·목표의 정보 시각과 지연에 맞춰 사전 고정한다. 같은 날짜의 52종목은 같은 시험 구간에 넣는다. 결측 처리·순위 기준·상관 계산도 학습 구간 안에서 정한다.

| 채점 | 기록 방식 |
|---|---|
| 가격 폭 | MAE, RMSE, 평균 편향; 같은 시작일·목표일의 원화와 수익률 |
| 방향 | 상승·하락·보합 규칙을 미리 고정; 유보 제외 여부와 분모 공개 |
| 확률 | 별도 보정된 방향 확률만 Brier 점수·보정 곡선; 모의 경로 수는 확률 인증 아님 |
| 범위 | 사전 고정 신뢰수준의 담김 비율과 interval score를 함께 기록 |
| 공통 장세 | KOSPI 기준 초과수익 채점과 KOSDAQ/업종·베타 통제 민감도 분석 병기 |
| 안정성 | 날짜 블록 단위 재표집, 종목별 성과, 상승·하락 국면, 자료 누락 구간 |

기본 개선량 D는 날짜별 ‘기존 손실−후보 손실’이다. 날짜 블록으로 신뢰구간을 만들고 공통 장세의 52배 중복 계산을 막는다. 방향 정확도 하나만 높아지고 가격 오차가 커지는 후보는 자동 승격하지 않는다.

승격 후보 조건: 사전 지정한 주 평가 지표의 개선 신뢰구간 하한 > 0, 미리 정한 실용 개선폭 충족, 범위·방향의 허용 악화 한도 충족, 입력 시점 검사 통과. 실용 개선폭·허용 악화 한도·블록 길이는 외부 시험을 보기 전에 확정해야 하며 현재 미확정이다. 여러 후보 비교에 따른 선택 편향도 보정한다. 250일은 마법의 인증 기준이 아니며 짧은 기간 결과는 잠정으로 남긴다.

현재의 52개만 과거 10년에 고정해 시험하면 생존·선정 편향이 있다. 상장 전 자료를 만들지 않고 평가 가능한 종목·날짜 수를 공개한다. 과거 검색·수급의 당시 원본을 못 구하면 재구성 연구와 앞으로 수집하는 실제 검증을 분리한다.

## 9. 개발 산출물과 처리 흐름

```text
52개 코드 레지스트리 → 원자료 수집·원문 보관 → 시점·기업행위 검사
→ 10일 특징 저장 → FOMO 지수와 자료 상태
→ 고정된 후보 모형 평가 → 진화 전망 발행 → 실제 종가 비교·오차 기록
```

추가할 모듈: fomo-registry(검색 별칭·단위), collectors(공식 접근 경로), feature-store(당시 원본), fomo-score-v2(지수), fomo-residual-model(조건부 보정), fomo-walkforward(검증), fomo-audit(발행 이력). 기존 fomo.mjs는 과거 버전으로 보존한다.

실행 계약의 의사코드:

```javascript
// 설계 명세: 아직 운영에 구현·실행한 코드가 아님.
for (const code of original52Codes) {
  const snapshot = await collectWithLimits(code, cutoff);
  saveRawAndFailures(snapshot);
  const features = buildAsOfFeatures(snapshot, cutoff, fixedFeatureVersion);
  const observation = scoreOnlySupportedTier(features); // missing != 0
  saveObservation(code, observation);
  const artifact = findFrozenValidatedModel(code, observation.tier);
  if (!artifact || !passesInputContract(features, artifact)) {
    recordAbstention(code, '모형 또는 입력 근거 부족');
    continue;
  }
  const candidate = predictWithFrozenArtifact(artifact, features);
  appendForecastVersion(candidate); // 원래 전망 수정 금지
}
```

핵심 검사: 52개 고유 코드 유지, 결측 0 대체 금지, 미래 공개 자료 차단, 검색 배치 척도 혼합 차단, 수정 전후 보존, 뉴스 중복 제거, 실제 거래대금 단위 검증, 같은 입력 중복 발행 방지, 종목 간 자료 혼입 차단, 공통 평가 날짜 분리, 운영 반영 상태와 화면 일치.

## 10. 화면에 보여줄 것

종목 그래프 옆에 ‘FOMO 관측 지수’, ‘기준 거래일’, ‘예측 반영 상태’를 짧게 둔다. 누르면 관심·참여·추격의 변화, 과열 요인, 자료 출처, 이전 발행 대비 모델 조정량을 보여준다. 자료가 없으면 ‘낮음’이 아니라 ‘미확보’다.

날짜 설명 예시의 형식: “투자 검색 증가와 개인 매수 참여가 관측됨. 기존 뉴스 모형에 비해 이 날짜의 모형 예상값이 얼마 조정됨. 근거 기간·검증 상태 표시.” 실제 숫자와 계수가 없으면 예시 숫자를 운영 화면에 넣지 않는다. 이 설명은 모형의 계산 이유이며 실제 주가 움직임의 확정 원인이라는 뜻이 아니다.

메인 그래프는 현재 선택한 전망 하나에 집중한다. 원래 전망과의 비교는 펼침으로 제공한다. 기존 기준선·봉인 기록·실제 종가와의 채점은 보존한다.

## 11. 제작 순서와 완료 증거

1. 52코드 레지스트리와 기존 가격 열기 재현: 코드 수·입력 해시·과거 결과 보존 확인.
2. OHLCV·실제 거래대금·개인 수급·검색부터 확보: 종목별 성공/실패·사용 가능한 과거 길이를 표로 발행. 선택형 게시자 수 때문에 전체 진행을 막지 않음.
3. 핵심 지수 병행 관측: 운영 가격은 그대로 두고 매일 점수·자료 상태·시각 기록.
4. 과거 시간순 시험과 향후 고정 모형 시험: 기본/가격만/핵심/과열 후보를 같은 날짜로 비교.
5. 통과 모형만 진화 전망에 적용: 계수·모형 버전·입력 원문·변경량을 재현 가능하게 저장.
6. 매일 실제 종가로 채점: 데이터 문제, 방향 계수 문제, 크기 문제, 돌발 사건, 설명 미확보를 구분. 실패했다고 당일 실제값에 맞춰 과거 식을 바꾸지 않음.

수집 완료·지수 계산 완료·예측 반영·성능 검증은 각각 다른 상태다. 52개 점수를 억지로 채우는 것보다 52개 모두의 확보 상태와 적용 여부가 정확히 드러나는 것이 완료 조건이다.
