## 수집기가 검사하는 것
요청한 과거 빈티지와 응답 날짜 일치, 누락된 페이지, 중복 날짜, 미래 날짜, 잘못된 숫자, HTTP 실패, 8MB 크기 제한, 요청수 및 시간 제한. 인증 실패나 요청 제한에 걸리면 연속 요청을 중단합니다. API키가 로그·보관 출처 URL에 남지 않도록 했습니다.

ALFRED의 일자별 빈티지는 발표 시각까지 입증하지 않습니다. 그래서 availableAt=null, intradayAvailabilityVerified=false, approvedForProduction=false를 유지합니다. 7일을 늦춰 썼다는 가정으로 실제 공개 시각 확인을 대신하지 않습니다.

## 필요한 연결
1. 금리·환율 과거 빈티지: FRED 계정에서 본인 API키 발급 후 실행 서버 환경변수 FRED_API_KEY로 등록.
   https://fred.stlouisfed.org/docs/api/api_key.html
2. 52종목의 조정 OHLCV·수급 이력: KRX 서비스 승인·키 또는 이용권 있는 공급자의 일별 원자료. 국민연금과 기관 전체 수급은 구분해야 합니다.
3. 검색 관심 이력: NAVER DataLab 사용 설정과 NAVER_CLIENT_ID/NAVER_CLIENT_SECRET. 개인 매수·매도 이력은 별도 필요합니다.

API키를 공개 게시물·프런트엔드·배포 ZIP에 넣지 마세요. 서버 환경변수로 등록합니다. 인증 정보를 등록한 뒤 원본 소스 폴더에서 `node scripts/collect_alfred_vintages.mjs`를 실행합니다. 이 명령은 수집·검증 기록을 만들며 자동으로 모형에 승인하지 않습니다.
