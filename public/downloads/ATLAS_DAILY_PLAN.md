# ATLAS 7.1 — 전체 그래프와 종목별 날짜 설명

## 목표와 범위

기존 52종목, 2026-09-17~2026-10-30을 유지한다. 화면은 처음부터 전체 실제·예측선을 보여준다. 재생은 저장된 가격을 다시 만들지 않고 날짜 표시선과 설명만 옮긴다. 어떤 종목의 어떤 날짜를 선택해도 표시 가격·일별 증감·반영한 사건·해당 종목의 과거 표본·출처·유보 이유를 같은 자료에서 확인한다.

이 문서의 코드는 표시와 설명 계층이다. 주가 엔진은 atlas-news-7.0.0을 보존하며, 새로운 예측이나 미확인 뉴스의 영향률을 만들어 넣지 않는다. 화면 버전은 7.1.0이다.

## 평평하게 보인 실제 원인

저장된 최신 52개 중앙값 경로는 모두 서로 다르며, 완전히 수평인 경로는 0개였다. 초기 9/17 커서에 연결된 clipPath가 9/23부터 시작하는 52개 모형선을 모두 숨겼다. 기존 235px 카드에서 넓은 P10~P90까지 축에 넣으면 47종목의 중앙값 전체 변화가 5px 미만이었다.

사용된 312개 종목·사건 연결 중 253개는 선택된 중심 로그효과 μ=0이었다. μ=0은 뉴스 계산 실패나 변동성 0과 같지 않다. 실제로 삼성전자 9/30의 저장값은 μ=0이지만 중앙값 전일 대비 약 −0.513%, 모형 평균 약 +0.112%다. 이것은 서로 다른 통계량이며 어느 하나를 다른 것의 원인이라고 설명하지 않는다. 자세한 52종목 수치는 reports/daily-experience-flat-diagnosis.json에 있다.

해결은 전체 경로 표시, 명시적 축·범위 선택, 날짜별 정확한 수치 설명이다. 선을 다르게 보이게 하려고 임의 기울기나 미래 상승률을 넣지 않는다.

## 방정식

### 1. 표시 가격과 날짜

종목 i, 달력 날짜 d에 대해 다음 표시값을 사용한다.

```text
V(i,d) = 유효 실제 종가가 있으면 해당 실제 종가
         미래 거래일이면 저장된 모형 중앙값 Q50(i,d)
         휴장일이면 직전 거래일의 참고값(새 가격 행 아님)
         필요한 자료가 없으면 null
```

휴장일에는 캔들·실제 종가·모형 거래일 행을 생성하지 않는다. 날짜 칸은 선택할 수 있고 ‘휴장·직전 거래일 참고’라고 표시한다.

### 2. 전일 대비 변화

```text
ΔP(i,t) = P(i,t) − P(i,t−1)
r(i,t)  = P(i,t) / P(i,t−1) − 1
표시 %  = 100 × r(i,t)
```

t−1은 직전 거래일이다. 실제 종가는 직전 실제 종가, 모형 중앙값은 직전 모형 중앙값, 모형 평균은 직전 모형 평균과 각각 비교한다. 필요한 이전 값이 없으면 0%로 채우지 않고 미확보로 표시한다.

### 3. 뉴스의 방향 효과와 모형 가격

```text
과거 잔여반응 x(i,e,k) = log(P(i,τ)/P(i,τ−1)) − 직전 연속 20거래일 평균
중심 로그효과 μ(i,e) = 선택 λ × n/(n+8) × mean(x)
저장된 중심 수익률 효과 = exp(μ(i,e)) − 1
일별 가격 경로 P(i,t,b) = P(i,t−1,b) × exp(R(i,t,b))
중앙값 Q50(i,t) = quantile({P(i,t,b)}, 0.5)
```

λ의 선택, 동일 사건·같은 날짜의 유보 등은 기존 엔진의 저장된 결과를 읽는다. μ와 중앙값의 하루 변화는 같은 숫자가 아니다. 방향 효과가 0이어도 표본의 분산과 분포 모양은 달라질 수 있다. 근거 부족으로 제외한 뉴스에는 변화율을 부여하지 않는다.

### 4. 평균과 사건일 분포 비교

```text
g(i,t) = Σ w(j) × exp(R(i,t,j))
M(i,t) = M(i,t−1) × g(i,t)
모형 평균 차이 = M(i,t−1) × [g(사건일 분포) − g(평소 분포)]
```

이미 저장된 numericSummary.increment.logGrossMean을 이용해 g=exp(logGrossMean)을 얻는다. 일반일 분포가 동일한지와 현재 평균의 곱셈 항등식이 맞는지 검사한 뒤 비교한다. 없거나 모순되는 자료는 null이다. 이 값은 ‘같은 모형에서 분포를 바꾼 차이’이며 실제 뉴스의 인과 효과나 중앙값의 뉴스별 기여율이 아니다. `causal:false`를 함께 전달한다.

### 5. 종목별 설명의 근거 집합

```text
E(i,d) = {해당 가격 행, 해당 종목·날짜의 연결 사건,
          해당 종목 자체 과거 표본, 선택계수, 근거 출처, 유보 사유}
설명(i,d) = 검증된 E(i,d)의 수치와 상태를 한국어로 변환
```

같은 금리 발표라도 종목 i와 j의 표본·평균·선택계수·모형 가격은 따로 읽는다. 확인된 사업 설명이나 출처가 있는 전달경로만 인용한다. 기업의 매출·비용·수주로 이어지는 구체적 자료가 없으면 부족하다고 표시한다. 미래 결과나 실제 상승 원인을 만들어 문장을 채우지 않는다.

### 6. 전체 경로와 재생

```text
화면의 x(d) = 왼쪽 + (d − 9/17)/(10/30 − 9/17) × 그래프 폭
그래프 표시 영역 = 항상 전체 기간
재생 중이고 설명 대기 중이 아니면 1000ms 뒤 d ← 다음 달력 날짜
중요 뉴스가 있으면 playing=false, stop=해당 날짜
‘설명 확인·계속’ 전에는 날짜 변화=0
선택하지 않은 다른 종목의 상태 변화=0
```

## 검증과 보존

52종목×44일=2,288개 설명, 표본 0개, 회사별 뉴스 격리, 같은 공통 사건의 종목별 수치 차이, 휴장일, 실제와 모형의 증감, 축약 API, 원본 불변을 검사한다. UI에서는 재생 전 전체 52개 경로, 44개 날짜 칸, 미래 날짜 클릭, 휴장일 설명, 1초 기본값, 독립 재생, 연속 뉴스 정지, 원본·Worker 재계산 보존을 검사한다.

현재 엔진·입력·최초 전망·이전 모든 전망·실제 평가·실패 이력의 해시를 변경 전후 비교한다. 최종 기능 검사 수와 결과는 VALIDATION.md 및 reports/tests.tap을 따른다. 과거 10,000개 합성 수치 검사는 계산 구현 검사이며 새 시장 검증 횟수로 세지 않는다.

실제 예측 신뢰 확률은 null이다. 날짜별 자세한 설명이 있다는 사실은 예측의 적중을 인증하지 않는다. 브라우저 실행파일 부재로 실제 화면 픽셀 검증은 완료하지 못했으며, 빌드 UI의 동작은 jsdom·실제 Worker와 색상 대비 검사로 확인한다. 실제 Netlify 배포는 별도다.
