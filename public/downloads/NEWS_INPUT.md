# ATLAS 7 뉴스 입력 기준

현재 엔진 atlas-news-7.0.0. 52종목 전체를 대상으로 수집하되 확인한 사건만 수동 검토를 거쳐 누적 승인한다. 원문 수집은 사건 승인이나 가격 영향 입증이 아니다.

- `node scripts/collect52.mjs`: 전역·호스트별 제한, 재시도·기한·회로 차단·원문 SHA·변경 이력. `reports/collection52`에 52종목별 결과와 미확인 링크·날짜 후보 저장.
- `npm run refresh`: NAVER 가격, 공식 거시 일정, 서버 런타임 회사 출처 수집. 정상 환경 프록시가 필요하면 Node24 `--use-env-proxy` 또는 `NODE_USE_ENV_PROXY=1`. 제한 우회 금지.
- `scripts/install_rebuild52.mjs`는 이번 사용자 승인 개편 1회용. 일상 반복 실행 금지. 기존 `install_researched_news.mjs`는 새 누적 검토 릴리스에만 사용.
- 필수: 기존 종목 코드·경제 사건 ID·단계·정확한 날짜·한국 반영일 배치 근거·공개 날짜·확인 시각·발행사/규제기관/주최자 원문 본문·대상 관계. 기업행위와 시장 예상 자료는 확보 여부를 별도로 표시.
- 게시 시각을 모르면 null. firstObservedAt/availableAt는 실제 관측 시각이며 과거 공개 시각을 복원한 것이 아니다.
- 이미 나온 사실은 `announced`와 publicationDate/발행지 timezone을 사용한다. 미래 일정으로 재분류하지 않는다. 정확한 공개 시각 미확보 시 한국 표시일은 보수적 배치이며 최초 반응일 확정이 아니다.
- 여러 기사는 한 경제 사건으로, 하나의 증자에 대한 기준일·권리 상장은 economicEventId 하나와 서로 다른 phaseId로 기록. 같은 날 중복 충격 금지.
- 검증 후보·설명 일정·유보를 구분한다. n≥5는 연구 분포 최소 조건일 뿐 정밀도 인증이 아니다. 통계 자격에는 동종·동일 기업·당시 정보·연속 기준 기간·기업행위/빈티지·목표 오차와 독립성 검토가 필요하다.
- 기존 사건 수정은 mergeNews 변경 전후 저널을 이용한다. 개별 사용자 수정과 동일 ID 충돌을 보존한다. 신규 사건 추가만으로 과거 기준시각 계산을 바꾸지 않는다.

최신 사건·미확보 현황은 NEWS_RESEARCH_52.md와 JSON을 확인한다. 아래는 이전 입력 계약과 조사 이력으로 보존한다.

# 종목별 뉴스 입력 — ATLAS 6

상승률·확률을 임의로 입력하지 않습니다. 미래의 확인된 일정과 같은 종류·같은 범위의 과거 사건을 넣으면, 엔진이 해당 종목의 실제 가격 반응으로 계산합니다. 현재 확인 수량과 종목별 부족 근거는 NEWS_RESEARCH_52.md에 기록합니다.

종목 카드의 ‘뉴스·계산값 보기’ → ‘이 기업 뉴스 JSON 추가’는 선택한 기업 하나만 대상으로 하는 사건을 받습니다. 다른 회사의 사건 ID를 덮어쓰거나 전체 뉴스로 확장할 수 없습니다. 지수·업종·시장 뉴스는 ‘예정 뉴스·근거’ 화면에서 추가합니다. 입력을 저장한 다음 ‘새 전망 계산’을 실행하면 새 버전에 반영하며 이전 전망은 보존합니다.

최상위 형식은 `{"events":[]}`입니다. 가짜 미래 사건이 실행되지 않도록 빈 배열로 제공합니다.

| 공통 필드 | 의미 |
|---|---|
| id | 실제 사건의 고유 ID. 재게시·수정 일정은 같은 ID |
| kind | 동일 종류 반응을 묶는 키. 기업은 회사코드+실적발표 종류 권장 |
| name | 원문으로 확인한 제목 |
| announcementDate | 실제 현지 발표 예정일 / 과거 실제 발표일 |
| targetDate | 발표 시각·휴장일을 반영한 한국 거래일 |
| availableAt | 그 일정이 공개된 ISO 시각. 모르면 최초 확인 시각 |
| scope | 아래 범위 객체 |
| status | scheduled / 철회 시 withdrawn |
| sources | `[{"name":"원문 이름","url":"공식 HTTPS URL"}]` 및 publishedAt/retrievedAt |
| channel | 매출·비용·금리 등 전달 경로 설명. 수익률 숫자가 아님 |

범위 객체 예시(실제 뉴스가 아닌 형식 설명):

| 범위 | scope 객체 |
|---|---|
| 기업 | `{"type":"company","codes":["005930"]}` |
| 업종 | `{"type":"sector","sectors":["반도체와반도체장비"]}` |
| 시장 공통 | `{"type":"market"}` — CPI/PPI/JOBS/JOLTS/FOMC/BOK만 허용 |
| 지수 | `{"type":"index","name":"지수명","codes":["대상 6자리 코드"],"membership":{"url":"구성 대상 근거 HTTPS URL","availableAt":"공개 ISO 시각","effectiveFrom":"YYYY-MM-DD","effectiveTo":"YYYY-MM-DD"}}` |

지수 코드는 이 52종목 중 근거로 확인한 대상 목록입니다. 이름만으로 모든 주식을 붙이지 않습니다. 구성 근거는 기준 시각 이전에 공개되어야 하고 사건 반영일에 적용되어야 합니다. 코드·업종명은 입력의 실제 목록과 일치해야 합니다. 출처 URL이 있다는 것만으로 원문 진실성이나 인과관계를 자동 검증한 것은 아닙니다.

과거 사건도 같은 범위를 명시합니다. 과거 기업 A의 실적 발표가 기업 B의 학습 표본으로 들어가지 않습니다. 표본 5건 미만은 계산 제외. 시간순 검증 3회 미만이면 평균 방향 효과는 0. 알려진 복수 사건이 같은 종목·같은 날에 겹치면 결합 반응 근거가 없어 개별 효과를 유보합니다. 음수·손실이라는 이유로 소거하지 않습니다.

기존 `target: all`은 알려진 6종 경제 발표만 시장 공통으로 해석합니다. 기존 코드 배열 형식은 기업 범위로 해석합니다. 알 수 없는 기업 뉴스의 전체 적용은 거부합니다.

자동 피드는 HTTPS `ATLAS_NEWS_FEED_URL`로 연결합니다. 신규 미래 사건은 최초 수집 시각부터 사용할 수 있고 범위가 바뀌면 새 수정 이력을 남깁니다. 운영 수집은 `npm run refresh`입니다.

새로 추가한 뉴스가 실제 적중률을 높인다고 자동 인증하지 않습니다. 원문·당시 공개 시각·가격 조정·예측 이후 실제 결과를 따로 검증해야 합니다. 상충한 동일 ID는 유보하며, 변경 전 내용은 수정 이력으로 보존합니다.


## 6.1.2 종목별 뉴스 추가

52종목의 확인 내역을 수록하고 45종목에 기업·업종 관련 일정을 연결했습니다. 남은 미래 일정은 시장 공통 6건, 지수 0건, 업종 11건, 기업 31건입니다. 기업 일정에는 한국가스공사의 적용월 시작 안내 1건이 포함됩니다. 나머지 7종목은 확정 날짜를 확보하지 못했습니다.

뉴스 탭의 52종목 조사 결과와 종목 상세의 조사 결과·출처에서 확인합니다. 기존 저장 자료에도 누적 뉴스 목록 전체가 이전되며 원본과 사용자 수정은 보존됩니다. 상세 근거는 NEWS_RESEARCH_52.md와 researched-news.json에 있습니다.

## 7.4 신문 역사 수치 입력

시장·업종·기업의 과거 기사 수치는 public/data/press-history.json에 별도로 보존합니다. 미래 예정 뉴스 목록(events)으로 복제하지 않습니다. 설치는 npm run research:press, 변경 수락 시 이전 데이터와 검사 보고서가 남습니다. API press-input은 expectedDataHash를 요구하며 현재 사용자 수정과 충돌하면 거부합니다. 과거 수치만으로 추가 방향 계수·상승 확률을 생성하지 않습니다.
