# ATLAS 집중형 재설계 기획서 · 180개 실행 기준
2026-09-28 · 기획 완료 / 제품 적용·실기 검수 미실행

## 결정
색상과 글씨의 기준은 첨부 image(5)의 Netlify 관리 화면으로 잡는다. 어두운 남색·밝은 글자·청록 선택 표시로 통일한다. 전체 화면의 본질은 “종목 선택 → 전망과 실제 비교 → 날짜별 이유 확인”이다. 180개는 기능 180개를 더하겠다는 뜻이 아니라, 삭제·통합·구현·검수의 기준 180개다.

## 사진에서 확인한 문제
첨부는 4장이 아니라 실제 전달된 6장(image5~10)을 모두 읽었다. 사진은 촬영 각도·확대율·브라우저 영역 때문에 CSS 픽셀이나 색상값을 정확히 측정하는 근거로 쓰지 않았다.
- image(5): Netlify 기준 화면. 어두운 바탕·밝은 산세리프 글자·청록 강조·명확한 탐색 계층.
- image(6): 그래프/조작 아래 큰 공백과 푸터가 보이고, 화면 자체와 내부 패널 스크롤이 병존.
- image(7): 올릭스의 제목·날짜·예측 가격이 겹치며, 그래프가 아래로 밀려 조작과 함께 보이지 않음.
- image(8): 같은 겹침을 가까이 확인. 이것은 취향 차이가 아닌 레이아웃 결함.
- image(9): 제목·보기 모드·필터·도움말·작업면 도구가 여러 행을 점유하고 차트가 화면 아래쪽으로 내려감.
- image(10): 자료 상태·상위 탐색·재생 안내·제목·모드·필터의 누적 높이가 집중을 끊음.

이전 460개 자동 검사 통과는 이 시각적 결함이 없다는 증거가 아니었다. 이번 기획은 사진을 결함 증거로 취급한다. 원인은 CSS 우선순위·Grid 행 배치 충돌 등을 의심할 수 있으나, 이 기획에서 현재 배포 코드의 computed style을 조사하지 않았으므로 원인 확정과는 구분한다. Chrome 기본 브라우저 안내·탭·북마크·Windows 작업 표시줄은 ATLAS 내부 요소가 아니다. 앱은 그 영역을 빼고 남은 뷰포트에 맞춰야 한다.

## 색상·서체 제안
Netlify Spark UI(S1)에는 본문 Instrument Sans, 제목 Figtree, 코드 Martian Mono가 명시되어 있다. 이를 Netlify 관리 화면의 정확한 글꼴이라고 단정하지 않는다. ATLAS는 한국어 비중이 높으므로 한글은 Noto Sans KR 계열을 후보로 두고 혼합 글꼴·숫자 정렬·라이선스를 구현 단계에서 검수한다. 일반 가격 숫자는 본문 서체의 tabular-nums를 우선하고, 코드용 고정폭 글꼴을 전체 본문에 쓰지 않는다.

아래 HEX와 크기는 공식 Netlify 값을 복제한 것이 아니라 ATLAS용 제안이다.

Netlify 로고는 가져오지 않는다. ATLAS 이름과 고유 마크를 유지한다. 청록색은 상승 의미가 아니라 선택·행동 의미다. 장식 경계색은 조작의 유일한 식별 단서로 쓰지 않는다.

## 새 배치와 높이 예산
PC 기준 상단 48px 헤더(ATLAS·종목/뉴스/성적/진화·계정), 44px 문맥 도구 행(자료 기준·필터·보기·설정)으로 통합한다. 큰 소개 제목은 작업면에서 제거한다. 자료 실패 요약은 배지로 상시 노출하고 상세만 펼친다.

1366×640 **브라우저 콘텐츠 뷰포트**의 설계 예산: 작업면 높이 = 640−48−44−24 = 524px. 작업면 안에서 종목 행 56 + 비교 행 64 + 차트 256 + 재생 44 + 날짜 44 + 내부 간격 16 = 480px를 우선 배분하고 나머지 44px를 라벨·반응형 여지로 둔다. 이 숫자는 구현 후 실측할 목표이며 현재 달성값이 아니다.

가로 예산은 외곽 24px를 뺀 뒤 목록 208px, 설명 약 288~304px, 두 간격 24px를 제외한 나머지를 차트에 배정한다. 1280×600에서도 같은 계산으로 약 216px 이상의 차트 높이를 우선 확보한다. 긴 이름·확대 글꼴에서는 숫자보다 잘림 방지가 우선이다.

- PC: 왼쪽 종목 목록 / 가운데 이름·비교 숫자·그래프·재생·날짜 / 오른쪽 이유·근거.
- 1024px 미만: 목록은 선택 서랍, 설명은 접을 수 있는 패널로 바꾼다.
- 휴대폰: 선택 종목 → 비교 숫자 → 그래프 → 재생 줄. 이유는 하단 시트로 연다.
- 낮은 높이·200% 확대: 글자를 강제로 축소하지 않고 단일 열과 자연 스크롤을 허용한다.
- 정상 PC에서는 목록과 긴 설명만 독립 스크롤한다. 그래프·그 안의 카드에 또 스크롤을 만들지 않는다.

## 구현 순서와 완료 기준
A. 결함 재현·원본 보관 → B. 중복 CSS와 행 배치 정리 → C. 높이·너비 구조 구현 → D. 색·한글·숫자 체계 적용 → E. 날짜·재생·뉴스 연결 → F. 실제 브라우저/휴대폰 검수 → G. ZIP와 배포 상태 확인.

현재 작업은 기획서 제작이다. 제품 코드를 변경하거나 사이트에 배포하지 않았다. 계획의 180개 항목은 모두 미구현 상태로 시작한다. 우선순위 P0는 겹침·잘림·정보 오해와 출시 검증, P1은 완성도를 높이는 후속 구현이다. 항목 번호 자체가 작업 순서는 아니다. 구현 때 기존 데이터·방정식·뉴스와 원본 전망은 보존한다.

출시 조건: 핵심 여정 작동, 사진의 겹침 재발 0건, 기준 뷰포트에서 그래프·재생 줄 동시 가시, 확대·키보드·긴 문장 검수, 원본 해시 일치, 실제 ZIP 열기. 실기 확인을 못 했다면 ‘시각 검수 미완료’로 남기며 자동 테스트 수로 대신하지 않는다.

|178|**실배포 별도 확인** — ZIP 완성과 사이트 적용을 다른 상태로 보고한다.|미배포를 배포 완료라고 부르지 않음|
|179|**복구 가능 릴리스** — 이전 버전과 새 버전의 식별자·해시를 보관한다.|배포 실패 시 이전 상태로 돌아갈 수 있음|
|180|**완료 보고의 기준** — 전후 화면·미해결 목록·검사 결과를 함께 전달한다.|남은 실기 검수와 데이터 제한을 숨기지 않음|
