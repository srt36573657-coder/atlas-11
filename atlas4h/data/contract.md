# 자료 약속 — ATLAS 4시간 엔진 (첫 실행 4번)

4시간 엔진이 쓰는 숫자는 모두 이 약속을 지킵니다.
변수와 출처 목록은 `variables.json`, 한눈 표는 `README.md` 에 있습니다.
규칙 등급(명령문 「규칙 등급」): 아래 규칙은 **기본**(올리기만 한다), 허용 폭·문턱·시간 같은 숫자는 **조정**(시장 점수로 바꾼다), 「넘지 않는 선」에서 온 것은 **절대**입니다.

## 값 하나에 붙는 것 (예시 — 2026-09-30 옛 엔진 실제 수집에서)

```
{
  "variable": "sox",
  "value": 12629.16,
  "unit": "지수 포인트",
  "observedAt": "2026-09-29T21:15:59Z",
  "fetchedAt": "2026-09-29T22:27:47.436Z",
  "source": "네이버 증권 해외지수 일별",
  "sourceUrl": "https://api.stock.naver.com/index/.SOX/price?page=1&pageSize=10",
  "rawSHA256": "(받은 바이트 그대로의 sha256)",
  "marks": ["한 출처"],
  "reason": null
}
```

- `observedAt` = 시장에서 그 값이 생긴 때 (원문 `2026-09-29T17:15:59-04:00` 을 UTC 로 바꾼 것)
- `fetchedAt` = 우리가 받은 때
- `marks` = 아래 「표시」 가운데 붙는 것 모두. 없으면 빈 칸 `[]`
- `value` 가 없으면 `null`, 그리고 `reason` 에 까닭 한 줄

## 표시

| 표시 | 뜻 |
|---|---|
| 옛값 | 값이 생긴 지 4시간 넘음 |
| 장 닫힘 | 시장이 닫혀 새 값이 원래 없음 (옛값과 함께) |
| 끊김 | 받으려 했는데 못 받음 (옛값과 함께) |
| 한 출처 | 출처 하나로만 확인됨 |
| 확인 중 | 두 출처가 다름 → 이 고리에서 안 씀 |
| 없음 | 숫자가 없음 → 짐작하지 않음 |
| 늦은 확인 | 둘째 출처가 나중에 나와 다시 맞춰 봄 (같음/다름) |
| 가격 제한 | 상한가·하한가에 닿음 |
| 거래정지 | 그 종목 거래가 멈춤 |
| 크게 바뀜 | 앞 고리보다 문턱 넘게 바뀜 |

## 규칙

### 출처
1. 변수마다 출처를 둘 적는다 — 첫째는 값, 둘째는 맞는지 보는 데 쓴다. (T7)
2. 같은 회사의 다른 주소는 출처 하나로 센다 — 둘째는 다른 회사·기관이어야 한다. (T7)
3. 값은 늘 첫째 출처 것을 쓴다 — 둘 중 마음에 드는 쪽을 고르지 않는다. (T8)
4. 첫째가 끊기고 둘째만 있으면 둘째 값을 「한 출처」로 쓴다. (K2)
5. 약관이 자동 수집을 막는 출처는 고르지 않는다 — 야후(약관 2(d)(ix)) · Cboe 공식 CSV(사용 전 사전 승인). (절대 · 넘지 않는 선)
6. 약관을 못 읽은 출처는 `terms` 칸에 「확인 필요」로 적고, 사장님이 정하기 전엔 그런 출처를 새로 늘리지 않는다. (절대 · 넘지 않는 선)
7. 열쇠(API 키)는 GitHub 저장소 비밀에만 두고 파일·기록·화면에 쓰지 않는다. (T3)

### 시각
8. 값마다 시각 둘을 붙인다 — `observedAt`(값이 생긴 때) · `fetchedAt`(받은 때). (T7 · T2)
9. 시각은 UTC 로 저장하고 출처의 시간대(예: America/New_York)를 함께 적는다. 화면은 한국 시각. (T2)
10. 날짜만 있는 값은 그날 가장 늦은 때로 본다 — 시장 값은 그 시장 마감, 공시는 23:59:59. (T2 · T17)
11. 봉인 시각보다 늦은 `observedAt` 이나 `fetchedAt` 을 가진 값은 쓰지 않는다. (T2 · 절대)
12. 뉴스·공시·검색 결과는 게시 시각이 봉인 시각 전인 것만 쓰고, 게시 시각이 없으면 안 쓴다. (T17)
13. `observedAt` 이 봉인 시각보다 4시간 넘게 앞서면 「옛값」을 붙인다. (T7)
14. 「옛값」에는 까닭을 함께 단다 — 「장 닫힘」 또는 「끊김」. (K2)

### 비교
15. 두 출처는 같은 기준끼리만 비교한다 — 같은 날짜 종가끼리, 또는 `observedAt` 이 5분 안인 값끼리. (T8)
16. 차이가 허용 폭(`variables.json` 의 `compare`)을 넘으면 「확인 중」으로 두고 그 고리에서 쓰지 않는다. (T8)
17. 허용 폭은 시작값이다 — 30거래일마다 실제 차이로 고치고, 고친 날과 까닭을 적는다. (조정)
18. 둘째가 늦게 나오면(FRED · KRX) 그 사이엔 「한 출처」로 쓰고, 나오면 다시 비교해 장부에 덧붙인다. (K2)
19. 늦은 비교에서 다르면 봉인된 판은 고치지 않고 「늦은 확인: 다름」 기록만 덧붙인다. (T1 · 절대)

### 없음
20. 숫자가 없으면 짐작하지 않고 `value` 를 `null`, 표시 「없음」, 까닭 한 줄을 남긴다. (절대 · 넘지 않는 선)
21. 결측을 0 으로 채우지 않는다 — 앞 값으로 채우지도 않고, 앞 값은 「옛값」을 달 때만 쓴다. (절대)
22. 해석이 안 되는 응답(주소·꼴이 바뀜)은 그 출처를 「끊김」으로 다룬다. (K2)

### 원문
23. 받은 바이트 그대로 보관하고, 그 sha256 을 값 옆에 적는다. (T3)
24. 같은 원문을 다시 해석하면 같은 값이 나와야 한다. (T4)

### 극한 — 휴장 엇갈림 · 자료 끊김
25. 미국만 쉰 날: 미국 변수는 「옛값 · 장 닫힘」 — 등락을 0 으로 바꾸지 않는다. (K1)
26. 한국만 쉰 날: 미국 등락을 다음 한국 거래일까지 곱해 쌓은 값을 따로 만든다. (K1)
27. 쉬는 날 판단은 거래소 달력으로 하고, 달력과 값의 날짜가 어긋나면 「확인 중」. (K1)
28. 두 출처가 다 끊기면 앞 값을 「옛값 · 끊김」으로 두고 새 계산을 하지 않는다(앞 판 다시 봉인). (K2)
29. 「한 출처」로 쓴 변수는 봉인에 그 표시를 남기고 감시 장부에 센다. (K2)

### 극한 — 상하한가 · 거래정지 · 크게 바뀜
30. 종목 값이 그날 상한가·하한가와 같으면 「가격 제한」 — 상하한가 = 전날 정규장 종가 ±30% 를 호가 단위로 맞춘 값. (K4)
31. 거래정지 종목은 값과 거래대금 모두 「없음(거래정지)」 — 0 으로 적지 않는다. (K4)
32. 「가격 제한」·「거래정지」 날은 민감도·밑값 계산에서 표시하고 뺀다. (K4)
33. 앞 고리보다 문턱 넘게 바뀐 변수는 두 출처를 다시 받아 확인한 뒤 「크게 바뀜」을 붙여 쓴다. (K6)
34. 문턱(시작값) = 그 변수의 지난 60거래일 하루 등락 크기 상위 5% — 다시 받은 값이 처음과 다르면 「확인 중」. (K6 · 조정)

### 시간
35. 모으기는 고리 시작 뒤 10분 안에 끝낸다 — 출처마다 15초 기다리고 한 번 더, 계속 실패하는 곳은 건너뛴다. (T9 · 조정)
36. 출처를 바꾸거나 더하면 날짜·까닭을 이 파일 맨 아래 「바꾼 기록」에 덧붙인다. (기본)
